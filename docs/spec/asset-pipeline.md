# アセットパイプライン仕様 — codex Image Gen

画像アセットは開発時にcodexのImage Genで生成し、リポジトリにコミットする。
ゲーム実行時に画像を動的生成することはない。

## スタイルガイド(全アセット共通)

- 世界観: ダークファンタジー。「壊れかけた機関が紡ぐ、まどろみの夢の世界」
- トーン: 暗め・彩度低め・コントラスト控えめ。夜霧、燭光、青灰と琥珀の対比
- 過度なゴア・グロテスク・性的表現は不可(ゲーム本編のトーン規定に準拠)
- タッチ: 絵画的なイラスト調で統一(ドット絵は目指さない。ドット絵の
  グリッド整合性はImage Genでは保証できないため)
- 文字を画像内に焼き込まない(タイトルロゴのみ例外として試みてよいが、
  破綻する場合はロゴをテキスト描画で重ねる)

### プロンプト共通接頭辞(初期案。改善したら本書を更新)

```
dark fantasy illustration, muted desaturated colors, dim candlelight and
blue-grey mist, melancholic dreamlike atmosphere, painterly style,
consistent game asset style, no text, no watermark
```

## 生成対象一覧(縦切り=ROADMAP M5)

| 種別 | 点数 | サイズ目安 | 用途 |
|---|---|---|---|
| タイトル背景 | 1 | 1920x1080 | タイトル画面 |
| 主人公立ち絵 | 1 | 縦長(~1024px高) | メニュー・会話 |
| NPC立ち絵 | 4 | 縦長(~1024px高) | 会話ウィンドウ横 |
| 敵グラフィック | 3 | 512x512程度 | 戦闘シーン |
| ボス「夢喰い」 | 1 | 768x768程度 | 戦闘シーン(2形態あれば尚可) |
| 背景 | 4-6 | 1920x1080 | 街・フィールド・ダンジョン・戦闘背景 |
| UI装飾 | 適宜 | 小 | ウィンドウ枠・カーソル等(シンプルに) |
| OP/ED静止画 | 2-4 | 1920x1080 | オープニング・エンディング |

- 立ち絵は背景透過が望ましい。透過生成が困難なら単色背景で生成して
  後処理(既存CLIツール可)で抜くか、円形ポートレート枠にトリミングして使う
- 各キャラクターは「同一人物性」が最重要。1枚目で人物の特徴を細かく言語化し、
  その記述を再利用して生成する(特徴記述はプロンプトファイルに残す)

## タイルマップの方針(重要)

- **タイル・スプライトシートはImage Genで生成しない**(グリッド整合性・
  透過・アニメフレーム一貫性が保証できないため)
- 縦切りではコード生成のプレースホルダータイル(単色+簡易パターン)を使う
- 拡張フェーズでCC0素材(Kenney等)への置換をBACKLOGで扱う
- プレイヤー・NPCのマップ上の見た目も同様にプレースホルダー
  (色付き矩形+向き表示)から開始してよい。立ち絵と会話で世界観を担保する

## ファイル管理規約

```
assets/
├── manifest.json           # 全アセットの台帳
├── prompts/
│   └── <asset-id>.md       # 生成に使ったプロンプト全文+生成メモ
├── title/
├── portraits/              # 立ち絵(player.png, npc-innkeeper.png, ...)
├── enemies/
├── backgrounds/
└── ui/
```

- ファイル名は英語kebab-case。`manifest.json`に
  `{ id, path, kind, sizePx, promptFile, createdAt, note }` を登録
- 生成し直した場合もプロンプトファイルを更新し、同一性を保つ
- クライアントは`manifest.json`経由でロードする(パス直書きをしない)

## 生成の進め方(M5での作業手順)

1. スタイル確立: まず背景1枚+主人公立ち絵1枚を生成し、トーンを確認
2. トーンが定まったら共通接頭辞を確定し、本書に反映
3. 残りを一括生成。人物は特徴記述を固定して一貫性を維持
4. 組み込み→E2Eスクリーンショットで見た目を確認
5. 不出来なものは個別に再生成(プロンプトファイルに試行メモを残す)
