# The Dreaming Engine — 設計書

日付: 2026-07-02
ステータス: 承認済み

## 概要

ゲーム実行中に生成AI(Claude Agent SDK)を組み込んだ、日本語のダークファンタジー2D RPG。
開発は人間が直接コードを書かず、codexの/goal・/loopによる超長時間自律駆動で行う。
画像アセットは開発時にcodexのImage Genで生成する。

## 決定事項

| 項目 | 決定 |
|---|---|
| 実行形態 | ブラウザ + ローカルNode.jsサーバー(自分専用・ローカル) |
| フロントエンド | Phaser 3 + TypeScript + Vite |
| サーバー | Node.js + Fastify + WebSocket + `@anthropic-ai/claude-agent-sdk` |
| 認証 | Claude サブスクリプションのAuth token(`CLAUDE_CODE_OAUTH_TOKEN`) |
| AIの役割 | NPC自由会話 / クエスト・イベント動的生成 / 情景描写 / GM的世界変化 |
| AIの権限 | 定義済みツール経由の構造化提案のみ。サーバー側で検証後に適用 |
| 戦闘 | ターン制コマンド戦闘。ロジックは決定論的コード、AIは演出のみ |
| 画像 | 開発時にcodex Image Genで生成しコミット。タイルは対象外 |
| 規模 | 縦切り(街1+ダンジョン1+ボス+セーブ)完成後、/loopで無限拡張 |
| 言語 | UI・AI応答ともすべて日本語 |

## AI統合 — DreamMasterモジュール

ゲーム状態スナップショット(現在地・時刻・パーティ・クエスト・好感度・会話要約)を
構造化コンテキストとして組み立ててClaudeを呼ぶ。世界への影響経路は6ツールのみ:

| ツール | 効果 | 検証 |
|---|---|---|
| `narrate` | 情景・戦闘描写 | 状態変更なし、長さ上限 |
| `speak` | NPC発話 | 状態変更なし、長さ上限 |
| `adjust_affinity` | 好感度変更 | 1回±10まで、0-100クランプ |
| `give_item` | アイテム付与 | ホワイトリスト+回数制限+好感度閾値 |
| `propose_quest` | サブクエスト発行 | テンプレートスロット(列挙型+レンジ)検証 |
| `trigger_world_event` | 天候・噂・小イベント | 定義済み型のみ、一晩3件まで |

- 検証失敗は黙って却下しログ記録、定型フォールバック文で進行
- AI不通・タイムアウトでもゲームは止まらない。メインクエストはAI非依存で完結可能
- モデル: 会話・描写 = `claude-haiku-4-5` / クエスト・夢シーン = `claude-sonnet-5`(設定で変更可)

## 「世界を守る」多層防御

1. **権限の壁**: ツール経由でしか世界に触れない。被害は常に有界
2. **ロールの壁**: 世界観憲法システムプロンプト。プレイヤー入力は`<player_utterance>`タグ内のデータとして渡す
3. **入力の壁**: 200文字上限・制御文字除去・レート制限(サブスク枠保護兼用)
4. **出力の壁**: 世界観逸脱パターン検知で定型文差し替え
5. **状態の壁**: セーブはサーバー管理。AIは直接書けない
6. **監査**: 全AI入出力・却下ログを記録。既知攻撃パターンのリグレッションテスト常備

## ゲーム仕様(縦切り)

- 世界観: 「壊れかけた夢の機関が生む、まどろみの世界」のダークファンタジー。命名・ロア細部はcodexの創作に委ねる
- 拠点の街: NPC4人(宿屋の主人=セーブ/宿泊、商人=店、情報屋=サブクエスト起点、謎の司祭=メインクエスト進行)
- フィールド1 + ダンジョン3層 + ボス「夢喰い」。撃破でエンディング=縦切り完成
- ターン制戦闘(攻撃/スキル/アイテム/逃走)、シンボルエンカウント、レベル/経験値/ゴールド/インベントリ
- AI見せ場: 酒場のサブクエスト動的生成、宿泊時の「夢のシーン」→翌朝の世界変化
- 操作: WASD/矢印移動、スペース調べる/話す、Escメニュー。会話は自由入力+選択肢併用

## アセットパイプライン

- codex Image Genで生成: タイトル、立ち絵(主人公+NPC4)、敵・ボス、背景、UI装飾
- 統一スタイルガイド(暗め・彩度低め・ダークファンタジー)を仕様化
- タイルマップは生成画像を使わない(グリッド整合性の問題)。コード生成プレースホルダー→将来CC0素材
- 生成プロンプトを`assets/prompts/`に保存、`assets/manifest.json`で管理

## テスト・自己検証

- 戦闘計算・インベントリ・クエスト状態機械・ツール検証層は純TSモジュール+Vitest
- `MockDreamMaster`でAI層を差し替え、E2E(Playwright)はモックAIで実行
- E2Eスモーク: 起動→新規→移動→会話→戦闘→セーブ→ロード+スクリーンショット
- `pnpm check`(typecheck+lint+test+build)が品質ゲート。通らない限りコミット禁止
- 実AI疎通は`pnpm test:ai-live`に分離(明示実行のみ)

## codex運用

- AGENTS.md: 開発憲法。作業開始時にJOURNAL/ROADMAP必読、終了時に更新義務
- ROADMAP.md: M0環境構築→M1マップ移動→M2戦闘→M3セーブ→M4 AI統合→M5アセット→M6縦切り完成
- /goal用プロンプト: M6完遂までの自己完結型駆動指示
- /loop用プロンプト: 1イテレーション=タスク1つ選択→実装→検証→コミット→ドキュメント更新。縦切り後はBACKLOGから無限拡張
