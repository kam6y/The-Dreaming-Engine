# The Dreaming Engine — 設計書

日付: 2026-07-02
ステータス: 承認済み

## 概要

ゲーム実行中に生成AI(Claude Agent SDK)を組み込んだ、日本語のダークファンタジー2D RPG。
開発は人間が直接コードを書かず、codexの/goal・/loopによる超長時間自律駆動で行う。
画像アセットは開発時にcodexのImage Genで生成する。

## 決定事項

| 項目 | 決定 |
|---|---|
| 実行形態 | ブラウザ + ローカルNode.jsサーバー(自分専用・ローカル) |
| フロントエンド | Phaser 3 + TypeScript + Vite |
| サーバー | Node.js + Fastify + WebSocket + `@anthropic-ai/claude-agent-sdk` |
| 認証 | サブスクの`CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token`で発行。Claude Code本体の公式認証手段)が既定(オーナーの要望)。環境変数で切替可能な認証抽象とし、動作しない・レート制限が問題の場合は`ANTHROPIC_API_KEY`へ差し替え(両方ある場合はOAuth優先)。Agent SDKドキュメントの標準はAPIキーのため、SDK経由の動作は`test:ai-live`で確認(詳細は`ai-integration.md`) |
| AIの役割 | NPC自由会話 / クエスト・イベント動的生成 / 情景描写 / GM的世界変化 |
| AIの権限 | 定義済みツール経由の構造化提案のみ。サーバー側で検証後に適用 |
| 戦闘 | ターン制コマンド戦闘。ロジックは決定論的コード、AIは演出のみ |
| 画像 | 開発時にcodex Image Genで生成しコミット。タイルは対象外 |
| 規模 | 縦切り(街1+ダンジョン1+ボス+セーブ)完成後、/loopで無限拡張 |
| 言語 | UI・AI応答ともすべて日本語 |

## アーキテクチャ

pnpm workspaceモノレポ:

```
The-Dreaming-Engine/
├── AGENTS.md                    # codexが毎セッション読む開発憲法
├── docs/
│   ├── spec/                    # game-design / world-lore / ai-integration / ai-guardrails / asset-pipeline
│   ├── prompts/                 # goal-vertical-slice.md(/goal用) / loop-expansion.md(/loop用)
│   └── progress/                # ROADMAP.md / JOURNAL.md / BACKLOG.md
├── packages/
│   ├── shared/                  # zodスキーマ・型定義(client/server共有)
│   ├── client/                  # Phaser 3 + Vite
│   └── server/                  # Fastify + WS + Agent SDK
├── assets/                      # 生成画像 + 生成プロンプト(コミット対象)
└── saves/                       # セーブJSON(gitignore)
```

- ブラウザ⇔サーバー: **WebSocketに一本化**(操作イベントの送信と、検証済みAI応答の
  全文送出。表示はクライアント側の疑似ストリーミング演出)。**GameStateの正本は
  サーバーが保持**し、クライアントの操作イベント(移動・戦闘コマンド・アイテム使用等)を
  サーバーが決定論的に適用する(セーブ・AI・検証がサーバー側で完結)
- サーバーは`127.0.0.1`のみにbindし、WS/HTTPのOriginヘッダを許可リスト検証、
  WS同時接続は1本のみ(許可Originからの新規接続受理時は既存を切断して置換。
  接続確立時にGameStateスナップショットで再同期。`ai-guardrails.md`第0層)。
  Vite開発サーバー(:5173)も`127.0.0.1`限定・`fs.deny`で`.env*`・`saves/`・`logs/`を
  配信拒否・CORS無効(同第0層)
- サーバー⇔Claude: Agent SDK。ゲーム内AIにはカスタムMCPツールのみ許可し、
  ファイル・Bash等の組み込みツールはSDK設定で除去または全面拒否する(サンドボックス。
  `bypassPermissions`不使用)

## AI統合 — DreamMasterモジュール

ゲーム状態スナップショット(現在地・時刻・パーティ・クエスト・好感度・会話要約)を
構造化コンテキストとして組み立ててClaudeを呼ぶ。世界への影響経路は6ツールのみ:

| ツール | 効果 | 検証 |
|---|---|---|
| `narrate` | 情景・戦闘描写 | 状態変更なし、長さ上限 |
| `speak` | NPC発話 | 状態変更なし、長さ上限 |
| `adjust_affinity` | 好感度変更 | 会話相手のみ、1回±10・1会話2回・NPCごと日次累積±20、0-100クランプ |
| `give_item` | アイテム付与 | ホワイトリスト+回数制限+好感度閾値(会話開始時点で判定)+所持枠空き |
| `propose_quest` | サブクエスト発行 | テンプレートスロット(列挙型+レンジ)検証 |
| `trigger_world_event` | 天候・噂・小イベント・ダンジョン変化 | 定義済み型のみ、一晩3件まで |

- 検証失敗は却下してログ記録(AIには世界観内の中立的なtool_resultのみ返し、
  理由は露出しない)、表示系ツールの承認が0件なら定型フォールバック文で進行
- AI不通・タイムアウトでもゲームは止まらない。メインクエストはAI非依存で完結可能
- モデル: 会話・描写 = `claude-haiku-4-5` / クエスト・夢シーン = `claude-sonnet-5`(設定で変更可)

## 「世界を守る」多層防御

0. **境界の壁**: `127.0.0.1`のみにbind・Origin許可リスト検証・WS同時1接続。
   悪意あるWebページからのローカルサーバー到達(クロスサイトWebSocket)を入口で遮断
1. **権限の壁**: ツール経由でしか世界に触れない。被害は常に有界
2. **ロールの壁**: 世界観憲法システムプロンプト。プレイヤー入力は`<player_utterance>`タグ内の
   データとして渡す(会話ログ・要約・噂などの全コンテキストタグの中身もデータ扱い)
3. **入力の壁**: 200文字上限・制御文字除去・タグ無害化(プレイヤー入力に限らず
   プロンプトへ注入する全テキスト対象)・レート制限(サブスク枠保護兼用)
4. **出力の壁**: 全文検査を通過した検証済みテキストのみ表示(疑似ストリーミング)。
   世界観逸脱パターン検知で定型文差し替え
5. **状態の壁**: セーブはサーバー管理。AIは直接書けない
6. **監査**: 全AI入出力・却下ログに加え、境界・保護イベント(Origin拒否・多重接続の
   置換/拒否・レート/クールダウン/上限ブロック・縮退の発動/解除)も記録。
   既知攻撃パターンのリグレッションテスト常備

## ゲーム仕様(縦切り)

- 世界観: 「壊れかけた夢の機関が生む、まどろみの世界」のダークファンタジー。命名・ロアの正は`docs/spec/world-lore.md`(未記載の細部のみcodexの裁量)
- 拠点の街: NPC4人(宿屋の主人=セーブ/宿泊、商人=店、情報屋=サブクエスト起点、謎の司祭=メインクエスト進行)
- フィールド1 + ダンジョン3層 + ボス「夢喰い」。撃破でエンディング=縦切り完成
- ターン制戦闘(攻撃/スキル/アイテム/逃走)、シンボルエンカウント、レベル/経験値/ゴールド/インベントリ
- AI見せ場: 酒場のサブクエスト動的生成、宿泊時の「夢のシーン」→翌朝の世界変化
- 操作: WASD/矢印移動、スペース調べる/話す、Escメニュー。会話は自由入力+選択肢併用

## アセットパイプライン

- codex Image Genで生成: タイトル、立ち絵(主人公+NPC4)、敵・ボス、背景、UI装飾
- 統一スタイルガイド(暗め・彩度低め・ダークファンタジー)を仕様化
- タイルマップは生成画像を使わない(グリッド整合性の問題)。コード生成プレースホルダー→将来CC0素材
- 生成プロンプトを`assets/prompts/`に保存、`assets/manifest.json`で管理

## テスト・自己検証

- 戦闘計算・インベントリ・クエスト状態機械・ツール検証層は純TSモジュール+Vitest
- `MockDreamMaster`でAI層を差し替え、E2E(Playwright)はモックAIで実行(直列実行 workers=1)。
  `AI_MODE`は未設定・不正値をmockに倒し、テスト実行下の`live`は起動時拒否
  (`pnpm test:ai-live`のみ例外のフェイルセーフ)
- E2Eスモーク: 起動→新規→移動→会話→戦闘→セーブ→ロード+スクリーンショット
- 通しプレイE2E(`pnpm test:e2e:full`)はコミット毎ではなく節目(M6整備後の
  マイルストーン完了時と縦切り完成時)のみ。
  テスト用のゲーム進行加速フラグは防御の弱体化にあたらない(`ai-integration.md`)
- `pnpm check`(typecheck+lint+test+build+シークレットスキャン)が品質ゲート。通らない限りコミット禁止
- 実AI疎通は`pnpm test:ai-live`に分離(明示実行のみ)
