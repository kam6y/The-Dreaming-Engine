# 対話系AI応答のストリーミング化(ストリーム+事後検証・撤回)設計書

- 日付: 2026-07-12
- 起点: オーナー指示「ユーザーと直接対話するAI生成については後からの検証を外して
  ストリーミング生成するようにし、なるべくユーザー側の待ち時間を無くしたい」
- ヒアリング確定事項:
  - 送出方式 = **ストリーム+事後検証・撤回**(届いたトークンをそのまま画面へ流し、
    完了後に出力壁を一括実行。違反時は表示を定型文へ差し替え、永続化しない)
  - 対象フロー = **会話(conversation)+サブクエスト生成(questGeneration)の speak のみ**
    (夢シーン・戦果描写・会話要約は現状維持)
- 本設計は `ai-guardrails.md` 第4層の「未検証テキスト非送出」に対する
  **オーナー指示(2026-07-12)による限定的な仕様改定**を伴う(4節)。

## 1. 背景と考え方

待ち時間の正体は検証コストではなくバッファリングである。出力壁は正規表現・
文字数チェックでコストはほぼゼロ。現状は `LiveDreamMaster.run()` がSDKのラン全体を
消費し終えてから一括検証・一括送出しているため、プレイヤーは応答文の生成完了+
後続ターンの完了まで何も見えない。

**方針: 検証は1つも削除しない。変わるのは「表示のタイミング」だけ。**

- 出力壁・ツール検証・監査ログ・履歴保存・キャッシュ格納・縮退カウントは
  従来どおり「完了後の全文」に対して実行し、それを正とする。
- ストリーミングは**画面表示専用の先行経路**。最終検証に落ちたら表示を
  定型フォールバック文へ差し替える(撤回)。
- 永続化(会話履歴・要約・キャッシュ・セーブ)には検証通過テキストしか入らない
  =guardrails第5層(状態の壁)は完全不変。
- キャッシュヒット(M26挨拶キャッシュ)は従来どおり即時全文(ストリーム不要)。
  縮退・クールダウン・直列化拒否・セッション総数上限も従来どおり
  (AIを呼ばない経路にストリームは発生しない)。

## 2. 実現手段(採用: 案A)

`query()` に `includePartialMessages: true` を渡し、`stream_event`
(`SDKPartialAssistantMessage` / `BetaRawMessageStreamEvent`)を購読する。
SDK 0.3.200 の型定義で対応を確認済み。

- `content_block_start`(`tool_use`, name=`mcp__dream__speak`)で捕捉開始
- `content_block_delta`(`input_json_delta.partial_json`)を累積し、
  `text` フィールド値を**増分JSON文字列パーサ**で抽出してコールバックへ渡す
  - 純TSモジュール。チャンク境界で切れたエスケープシーケンス
    (`\n` `\"` `\uXXXX` の途中切断)は完成まで保留する
  - `speak` 以外のツール(`adjust_affinity`・`propose_quest` 等)の入力は流さない
- `content_block_stop` で当該 speak の捕捉終了(1ターン複数 speak は逐次)

プロンプト・ツール定義・サンドボックス設定(`canUseTool` デフォルト拒否・
`disallowedTools`・`settingSources: []` 等)は**バイト不変**。

不採用案: B=会話応答を平文テキスト出力へ変更(憲法「応答は必ずspeakツールで」を
含む防御構造の大改造になる)、C=Messages API直叩き(認証抽象・サンドボックスの
作り直し)。いずれも変更範囲と防御リスクが過大。

## 3. サーバー側設計

### 3.1 DreamMaster インターフェース

- `DreamMasterRunOptions` にオプショナルな `onSpeakDelta?: (delta: string) => void` を追加。
- `LiveDreamMaster`: 対象2フローかつコールバック指定時のみ `includePartialMessages: true`
  を設定し、増分パーサ経由でデルタを発火する。タイムアウト2値(初回/全体)・
  失敗種別・`drainStream` の意味論は不変。
- 配線: セッション層(session.ts)がゲートキーパー→ターン実行器経由で
  `onSpeakDelta` を渡す(デルタ→`pushSender` への接続と start の遅延送出は
  セッション層の責務。ターン実行器はコールバックを素通しするだけで意味論を変えない)。
- `MockDreamMaster`: 同IFを実装し、定型応答テキストを決定論的なチャンク分割で
  同期的に発火してから従来の結果を返す(E2E決定論の維持)。

### 3.2 WSプロトコル(shared に4メッセージ追加)

| メッセージ | ペイロード | 意味 |
|---|---|---|
| `dialog-stream-start` | `{ speaker }` | 試行の開始。クライアントはストリームバッファをクリア(リトライ時は自然に「消えて再開」) |
| `dialog-stream-delta` | `{ text }` | 増分テキスト。既存 `pushSender` 経由で送出 |
| `dialog-stream-end` | `{ speaker, body }` | 最終**検証済み**全文。バッファをこの正文で置換(増分パースのずれ・正規化差分をここで吸収) |
| `dialog-stream-abort` | `{ speaker, body }` | 撤回。定型フォールバック文で表示を差し替え |

- いずれも zod スキーマを `shared` に追加(既存 `dialog`・`sleep-start` と同じ流儀)。
- **送出条件**: `stream-start` は各試行の**最初のデルタ発火時に遅延送出**する
  (デルタが1つも出ないまま失敗した試行では start/abort とも送らず、従来どおり
  通常の `dialog` メッセージでフォールバック文を返す)。`stream-abort` は
  「start を送った最終試行が失敗確定した」場合のみ送出する。
- 表示の最終状態は常に `stream-end`(検証済み全文)または `stream-abort`(定型文)、
  もしくは通常 `dialog`(ストリーム未発生時)=未検証テキストが画面に**残存**することはない。

### 3.3 ターン意味論(turn-executor)は不変

- リトライ1回・表示系承認0件(`display_zero`)判定・オール・オア・ナッシング・
  縮退状態機械・セッション総数上限はすべて現状のまま。
- ストリーム済みでも speak が最終検証で却下されれば従来どおり `display_zero`
  → リトライ(新しい `stream-start` でバッファクリア)または失敗確定(`stream-abort`)。
- 状態変更 effect(好感度・アイテム・クエスト提案)の適用と効果表示は
  従来どおり**最終検証後のみ**。ストリーム中に適用される状態変更は存在しない。
- 監査ログ: 従来の記録に `streamed` / `retracted` の注記フィールドを追加
  (機密マスクの無条件適用は不変)。

## 4. クライアント側設計

- 会話ウィンドウ: ストリームバッファを逐次追記表示。**ストリーム中は
  タイプライター演出を使わない**(非ストリーム文=フォールバック・キャッシュヒット・
  夢・戦果描写は従来どおりタイプライター)。
- `stream-end` で正文に置換、`stream-abort` で定型文に置換。
- ストリーム中の会話終了操作は既存の「応答待機中ブロック」がそのまま適用(仕様不変)。
- WS切断→再接続はスナップショット再同期が正(途中デルタは捨てる。
  `pushSender` 未設定時はデルタ送出をスキップ=sleep-start と同じ流儀)。

## 5. 仕様改定(オーナー指示による変更として記録)

- `ai-guardrails.md` 第4層に**対象2フロー限定の例外**を追記:
  「会話・サブクエスト生成の speak に限り、画面表示への未検証ストリームの先行表示を
  許可する。ただし(1)完了時の出力壁の全文実行、(2)違反時の表示撤回(定型文への
  差し替え)、(3)未検証テキストの非永続化(履歴・要約・キャッシュ・セーブへ入れない)、
  (4)監査記録、を必須とする」。実装チェックリストの該当項目も同旨に改定。
  **オーナー指示(2026-07-12)による改定である旨を本文に明記**する。
- `ai-integration.md`: speak の効果欄(「全文受領→出力壁→送出」)と
  「呼び出しフロー別仕様」へ同期の注記。ストリーミング節を追加。
- CLAUDE.md は変更しない(「弱める変更禁止」はClaude Codeの自律判断への禁止。
  今回はオーナーの明示指示であり、JOURNALに記録する)。

## 6. テスト

- ユニット:
  - 増分JSON文字列パーサ(境界エスケープ・複数speak・非speakツール無視・不正JSON耐性)
  - `LiveDreamMaster`: 偽ストリーム(`stream_event` 列)でのデルタ発火・
    タイムアウト時の途中打ち切り
  - ターン実行/セッション: 却下ターンで `stream-abort` が送出され effect が破棄される・
    履歴/キャッシュに未検証テキストが入らない・リトライで `stream-start` が再送出される・
    キャッシュヒット/縮退/クールダウンでストリームが発生しない
  - `MockDreamMaster` のチャンク発火の決定論
- 攻撃テストA(マニフェスト登録):
  - 「ストリーム済み→出力壁却下」で表示が撤回され、履歴・キャッシュ・セーブに
    未検証テキストが残らないこと
  - 既存の防御アサート(401字speak却下・逸脱パターン却下等)は一切緩めない
- E2Eスモーク: モックの最終正文は従来と同一テキストのため既存アサートは原則保持。
  必要な追随はストリーム完了(`stream-end` 置換後)を待ってからの検証に限る。

## 7. リスクと限界(受容事項)

- 違反テキスト(世界観逸脱等)が**完了までの数秒間、画面に出得る**
  (撤回されるが目には入る)。オーナーが受容済み。
- 増分パースのずれ・取りこぼしは `stream-end` の正文置換で必ず収束する
  (表示の最終状態は常に検証済み全文または定型文)。
- 体感効果は `AI_MODE=live` でのみ観測可能(モックはレイテンシゼロ)。
  実プレイでの確認は人間確認待ちとする。
