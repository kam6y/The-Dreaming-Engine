# /loop 用プロンプト — 1イテレーション定義(無限拡張)

以下のブロックをそのままcodexの `/loop` に与えて使う。
縦切り(ROADMAP M0-M6)完成前でも使える(その場合はROADMAPを優先して進める)。

---

日本語ダークファンタジー2D RPG「The Dreaming Engine」の開発を1イテレーション進めよ。

## 1イテレーションの手順

1. **現在地の把握**: `AGENTS.md` → `docs/progress/JOURNAL.md` 末尾 →
   `docs/progress/ROADMAP.md` の順に読む
2. **タスク選択**(この優先順で1つだけ選ぶ):
   a. JOURNALの「既知の問題」にE2Eやcheckを赤にするものがあれば、その修復
   b. ROADMAP(M0-M6)に未完了項目があれば、その最上位の項目
   c. 縦切り完成後は `docs/progress/BACKLOG.md` の最上位の未完了項目
      (大きい項目は分割してROADMAP末尾にM7+として展開してから着手)
3. **実装**: 選んだタスクを1-2時間相当以下に分解して実装する。
   関係する `docs/spec/` の仕様書を必ず読んでから書く。
   ゲームロジックにはユニットテストを付ける
4. **検証**: `pnpm check` と `pnpm test:e2e` を緑にする。
   緑にできない場合、変更を縮小またはrevertしてでも**緑の状態でイテレーションを終える**
5. **記録**: コミット(小さく、規約に従い)+ `ROADMAP.md`/`BACKLOG.md` のチェック更新
   + `JOURNAL.md` に新エントリ(次のイテレーションへの申し送りを必ず書く)

## 規律(毎イテレーション共通)

- 1イテレーション=1タスク。欲張らない。大きな作業は分割して次に回す
- 仕様(`docs/spec/`)が正。防御仕様(`ai-guardrails.md`)は絶対に弱めない
- 実AIを呼ぶテストを自動実行に組み込まない(`AI_MODE=mock` で開発する)
- 同じエラーに3回失敗したら方針転換し、JOURNALに記録して前進する
- `.env`・`saves/`・`logs/` をコミットしない。ブランチは `codex/dev`
- 新しい画像アセットが必要な場合は `docs/spec/asset-pipeline.md` に従い
  Image Genで生成し、manifest・プロンプト保存を怠らない
- リポジトリが壊れた状態(check赤・E2E赤)でイテレーションを終えることを禁ずる

## 終了条件

このループに自然な終わりはない(継続的拡張)。ただし以下の場合はループを
停止して人間の判断を仰ぐ旨をJOURNALに書き、作業を終了する:

- BACKLOGとROADMAPの未完了項目がすべて尽きた
- 人間の判断が必要な問題(仕様の矛盾、環境の破損、権限不足)で前進できない

## (参考)運用メモ — 人間(あなた)用

- ループの粒度: 1イテレーションが1コミット以上+JOURNAL 1エントリになる。
  進捗は `git log --oneline` と `docs/progress/JOURNAL.md` で追える
- 介入したいとき: `docs/progress/BACKLOG.md` の並び順を編集すれば、
  次イテレーション以降の優先順位を人間側からコントロールできる
- 定期確認の推奨: 数イテレーションごとに `pnpm dev` で実際に遊んでみて、
  気づきをBACKLOGに追記する(それが次のループの入力になる)
- 実AIの動作確認は人間が手動で: `pnpm test:ai-live` と、`.env` を設定した上での
  `pnpm dev`(モックでない方)での実プレイ
