# /goal 用プロンプト — 縦切り完成まで

以下のブロックをそのままClaude Codeの `/goal` に貼り付けて使う。

---

日本語ダークファンタジー2D RPG「The Dreaming Engine」の縦切り(vertical slice)を完成させよ。

## ゴール

`docs/progress/ROADMAP.md` のM0からM6までのすべてのチェックボックスを、
各マイルストーンの完了条件を満たした上で完了させる。最終状態は:

- タイトル→新規ゲーム→メインクエスト→ボス「夢喰い」撃破→エンディング→タイトル
  まで通しでプレイできる
- `pnpm check` と `pnpm test:e2e`(スモーク)が緑。M6完了時は通しプレイの
  `pnpm test:e2e:full` も緑(通しE2Eはコミット毎ではなく節目のみ: AGENTS.md「品質ゲート」)
- 主要シーンに生成画像アセットが組み込まれている
- すべてコミット済みで、`docs/progress/JOURNAL.md` が最新状態を反映している

## 最初にやること

1. `CLAUDE.md` を読む(このプロジェクトの憲法。全作業で従うこと)
2. `docs/progress/JOURNAL.md` の末尾エントリで現在地を確認する
3. `docs/progress/ROADMAP.md` で次の未完了マイルストーンを特定する
4. 対象マイルストーンに関係する `docs/spec/` の仕様書を読む

## 作業サイクル(これを完了まで繰り返す)

1. ROADMAPの次の未完了項目を1つ選び、1-2時間相当以下のタスクに分解する
2. 実装する。ゲームロジックはユニットテストを先に(または同時に)書く
3. `pnpm check` を緑にする(M0初期で未整備の場合は、まず整備すること自体をタスクとする。
   M1以降は `pnpm test:e2e` も)
4. 小さくコミットする(CLAUDE.mdのコミット規約に従う)
5. `ROADMAP.md` のチェックと `JOURNAL.md` のエントリを更新してコミットする
6. 次の項目へ

## 重要な規律

- 仕様(`docs/spec/`)が正。仕様にない細部は裁量で決めてJOURNALに記録する。
  仕様を変えたい場合は変えずに「仕様変更提案」としてJOURNALに書き、前進する
  (例外: 仕様書自身やBACKLOGが明示的に指示・許可する追記・更新は行ってよい。
  詳細はCLAUDE.md「ドキュメントマップ」直下の規定)
- ゲーム内AIの防御要件(`docs/spec/ai-guardrails.md`)は絶対に弱めない
- 開発・E2Eでは実AIを呼ばない(`AI_MODE=mock`)。`pnpm test:ai-live` を
  自動実行に組み込まない
- 同じエラーに3回失敗したらアプローチを変えるか、プレースホルダーで前進して
  JOURNALに既知の問題として記録する。1つの問題で止まり続けない
- プレースホルダーで前進した項目は、ROADMAPの当該項目に「(プレースホルダー:
  JOURNALの既知の問題を参照)」と注記し、チェックは付けない。以後の項目選択では
  注記付き項目をスキップして次へ進み、**完了宣言の前**(M6の他項目を終えた後)に
  一括で再訪する。解消できたら注記を外してチェックし、解消できないものは
  「人間確認待ち」としてJOURNALに記録して停止する(未解消のままチェックしない)
- ROADMAP/BACKLOGの「ブロック中: 理由」注記(/loop運用時に付与される)は尊重する:
  注記付き項目と、それに依存する項目は選択しない。注記を自分で外さない(解除は
  人間のみ)。選択できる項目が残らない場合は状況をJOURNALに記録して停止する
- `.env`・秘密情報・`saves/`・`logs/` をコミットしない。作業ブランチは `claude/dev`
- M5では `docs/spec/asset-pipeline.md` に従う。**画像は自作せず**、
  codex(`mcp__codex__codex`)への委譲で生成する。委譲済みの納品物が `assets/` に
  あればそれを検収して組み込み、不足分のみ追加委譲する(スタイルガイド・
  ファイル管理規約・プロンプト保存を遵守)。委譲できない場合は「人間確認待ち」として
  JOURNALに記録し、プレースホルダーのまま先へ進む
- ライブラリのAPIが不明なときは公式ドキュメントを調べる。
  特にClaude Agent SDK(`@anthropic-ai/claude-agent-sdk`)はM4実装前に
  必ず最新ドキュメントを確認する

## 停止・エスカレーション・人間確認待ち

- 完了条件のうち**人間にしか実行できない項目**(`pnpm test:ai-live`の実行、
  実AIでの実プレイ確認等)は、テストコード・実行手順の整備まで済ませた上で
  JOURNALに「人間確認待ち」として記録し、**ブロッカーにせず次の項目へ進む**。
  自分で`pnpm test:ai-live`を実行してはならない
- 人間の判断が必要な問題(仕様の矛盾、環境の破損、権限不足)で前進できない場合は、
  状況・試したこと・選択肢をJOURNALに書いて作業を停止する。
  未検証の項目にチェックを付けて先へ進むことは禁止

## 完了の宣言

M6の完了条件をすべて満たしたら、JOURNALに「縦切り完成」エントリを書き、
通しプレイのE2Eスクリーンショット一式の場所と、残っている「人間確認待ち」項目の
一覧を記載して作業を終了する。
